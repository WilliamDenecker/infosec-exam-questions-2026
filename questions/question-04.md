# Question 4

**Describe how authenticated Diffie-Hellman (DH) key exchange could work with elliptic curve cryptography (for a given elliptic curve $EC$ with given generator $G$ of known and given order $n$). What would be the mathematical operations to derive a single-use session key?**

*Hint: start from the original Authenticated DH key exchange (based on modular exponentiation).*

## Answer

### Original Authenticated Diffie-Hellman (Modular Exponentiation)

In the classical authenticated DH (ch2.2.4 p.10), two parties A and B have:
- Agreed public parameters: a large prime $p$ and a generator $g$ of a cyclic group of order $q$
- Long-term certified key pairs: $(a_{long}, g^{a_{long}} \bmod p)$ for A and $(b_{long}, g^{b_{long}} \bmod p)$ for B, with public keys certified by a CA (ch3.2 p.28–29)

**Protocol**:
1. A chooses ephemeral random $a \in \{1, \ldots, q-1\}$, computes $Y_A = g^a \bmod p$, signs it: $\sigma_A = Sign_{PR_A}(Y_A)$, sends $(Y_A, \sigma_A)$
2. B chooses ephemeral random $b \in \{1, \ldots, q-1\}$, computes $Y_B = g^b \bmod p$, signs it: $\sigma_B = Sign_{PR_B}(Y_B)$, sends $(Y_B, \sigma_B)$
3. A verifies $\sigma_B$ using $PU_B$ (from B's certificate); B verifies $\sigma_A$ using $PU_A$
4. Shared secret: A computes $S = Y_B^a \bmod p = g^{ba} \bmod p$; B computes $S = Y_A^b \bmod p = g^{ab} \bmod p$ — same value by commutativity of exponentiation
5. Session key: $K_{session} = KDF(S)$ — a key derivation function applied to the shared secret

The authentication step (signatures) prevents a man-in-the-middle substituting their own $Y$ values: without the long-term private key, an attacker cannot produce valid signatures on crafted ephemeral public values.

### Elliptic Curve Authenticated Diffie-Hellman (ECDH)

The translation from modular exponentiation DH to elliptic curve DH (ch2.2.4 p.10) is systematic:

| Classical DH operation | ECC equivalent |
|---|---|
| Group: integers mod $p$ | Group: points on elliptic curve $EC$ |
| Generator: $g$ (integer) | Generator: $G$ (point on $EC$, known order $n$) |
| Scalar exponentiation: $g^a \bmod p$ | Scalar multiplication: $a \cdot G$ (point added to itself $a$ times) |
| Discrete log problem in $\mathbb{Z}_p^*$ | ECDLP: given $a \cdot G$, find $a$ — computationally infeasible |
| Private key: large integer $a$ | Private key: large integer $a \in \{1, \ldots, n-1\}$ |
| Public key: $g^a \bmod p$ (integer) | Public key: $a \cdot G$ (a point $(x, y)$ on $EC$) |

**Setup**:
- Both parties know: elliptic curve $EC$, generator $G$, order $n$
- A has long-term key pair: private key $a_{long} \in \{1, \ldots, n-1\}$, public key $A_{long} = a_{long} \cdot G$ (certified by CA)
- B has long-term key pair: private key $b_{long} \in \{1, \ldots, n-1\}$, public key $B_{long} = b_{long} \cdot G$ (certified by CA)

**Ephemeral ECDH Protocol**:

**Step 1 — A generates and signs ephemeral key**:
- A chooses uniformly random ephemeral scalar $a \in \{1, \ldots, n-1\}$ (fresh per session; discarded after)
- A computes ephemeral public key: $\hat{A} = a \cdot G$ (a point on $EC$)
- A signs $\hat{A}$ using long-term private key $a_{long}$: $\sigma_A = ECDSA(a_{long},\ \hat{A})$ (ch2.2.3 p.85–87)
- A sends $(\hat{A},\ \sigma_A)$ to B

**Step 2 — B generates and signs ephemeral key**:
- B chooses uniformly random ephemeral scalar $b \in \{1, \ldots, n-1\}$ (fresh per session; discarded after)
- B computes ephemeral public key: $\hat{B} = b \cdot G$ (a point on $EC$)
- B signs $\hat{B}$ using long-term private key $b_{long}$: $\sigma_B = ECDSA(b_{long},\ \hat{B})$
- B sends $(\hat{B},\ \sigma_B)$ to A

**Step 3 — Mutual authentication**:
- A verifies $\sigma_B$ using $B_{long}$ (retrieved from B's X.509 certificate, ch3.2 p.28–29): confirms $\hat{B}$ was generated by the authentic B
- B verifies $\sigma_A$ using $A_{long}$: confirms $\hat{A}$ was generated by the authentic A
- If either verification fails: abort

**Step 4 — Shared secret derivation** (mathematical core):
- A computes: $S = a \cdot \hat{B} = a \cdot (b \cdot G) = (ab) \cdot G$
- B computes: $S = b \cdot \hat{A} = b \cdot (a \cdot G) = (ab) \cdot G$
- Both arrive at the **same point** $S = (ab) \cdot G$ on $EC$, by the associativity and commutativity of elliptic curve scalar multiplication: $a \cdot (b \cdot G) = b \cdot (a \cdot G) = (ab) \cdot G$

An eavesdropper who observes $\hat{A} = a \cdot G$ and $\hat{B} = b \cdot G$ cannot compute $(ab) \cdot G$ without solving the Elliptic Curve Diffie-Hellman problem (ECDHP), which is computationally infeasible for well-chosen curves and sufficiently large scalars.

**Step 5 — Session key derivation**:
- Extract the $x$-coordinate of the shared point: $S_x = x\text{-coordinate of } (ab) \cdot G$
- Derive session key: $K_{session} = KDF(S_x \| \text{context})$

The KDF (e.g., HKDF using SHA-256) is applied because the raw $x$-coordinate is not uniformly random and may have structure; the KDF produces a uniformly distributed key suitable for AES or other symmetric algorithms (ch3.6 p.18 — this is the ECDHE key exchange used in TLS 1.3).

The ephemeral scalars $a$ and $b$ are **discarded** immediately after $K_{session}$ is derived. This is essential for forward secrecy (ch3.6 p.37): if $a_{long}$ or $b_{long}$ is later compromised, past session keys cannot be reconstructed because $a$ and $b$ no longer exist.

---

### Why Authentication Is Essential (ch2.2.4 p.10)

Without signatures on the ephemeral public keys, the protocol is vulnerable to a man-in-the-middle attack:
- Attacker intercepts $\hat{A}$ and sends their own $\hat{M}$ to B
- Attacker intercepts $\hat{B}$ and sends their own $\hat{M}'$ to A
- Attacker shares secret $S_{AM}$ with A and $S_{MB}$ with B
- A and B each believe they share a key with each other — but both keys go through the attacker

The ECDSA signatures on $\hat{A}$ and $\hat{B}$, verified against certificates from a trusted CA, prevent this: the attacker cannot produce a valid signature on a crafted ephemeral key without knowing $a_{long}$ or $b_{long}$.

---

### Summary of Mathematical Operations

| Step | Party A | Party B |
|---|---|---|
| Choose ephemeral scalar | Random $a \in \{1 \ldots n-1\}$ | Random $b \in \{1 \ldots n-1\}$ |
| Compute public share | $\hat{A} = a \cdot G$ (EC point mult.) | $\hat{B} = b \cdot G$ (EC point mult.) |
| Sign ephemeral share | $\sigma_A = ECDSA(a_{long}, \hat{A})$ | $\sigma_B = ECDSA(b_{long}, \hat{B})$ |
| Verify partner's share | Verify $\sigma_B$ using $B_{long}$ | Verify $\sigma_A$ using $A_{long}$ |
| Compute shared secret | $S = a \cdot \hat{B}$ (EC point mult.) | $S = b \cdot \hat{A}$ (EC point mult.) |
| Derive session key | $K = KDF(S_x)$ | $K = KDF(S_x)$ |
| Discard ephemeral key | Erase $a$ | Erase $b$ |
